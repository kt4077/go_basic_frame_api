# 新闻资讯插件数据库说明

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 插件 ID | `news` |
| 插件版本 | `1.1.4` |
| 核心版本 | `0.0.2` |
| 文档更新时间 | `2026-09-25` |

## 2. 插件业务表

| 表名 | 用途 | 移除时保留 | Purge 时删除 |
| --- | --- | --- | --- |
| `plg_news_category` | 新闻分类 | 是 | 是 |
| `plg_news_article` | 新闻文章、正文、发布状态和浏览量 | 是 | 是 |

`v1.1.0` 在文章表新增 `enable_status`（`1` 启用、`2` 禁用）与 `virtual_view_count`。真实浏览量仍写入 `view_count`，接口返回的展示浏览量由两者相加得到，避免虚拟数量污染真实统计。

插件不创建 `sys_` 前缀业务表。`sys_plugin`、`sys_plugin_migration`、`sys_plugin_menu` 和 `sys_plugin_install_log` 由宿主安装器维护，不属于插件业务表。

## 3. 表内关系

| 当前表及字段 | 引用表及字段 | 关系 | 数据库外键 | 删除规则 |
| --- | --- | --- | --- | --- |
| `plg_news_article.category_id` | `plg_news_category.id` | 多篇文章属于一个分类 | 无，逻辑关联 | 分类下存在未删除文章时，业务逻辑拒绝删除分类 |

当前版本没有物理外键。关联字段 `category_id` 已建立索引，管理端查询通过 Resp 中的 GORM 关系进行预加载。

## 4. 外部数据库引用

### 4.1 插件引用核心表

无。新闻插件业务表没有外键引用核心 `sys_*` 表，也不会直接修改核心业务表。

### 4.2 插件引用其他插件表

无。新闻插件 `Dependencies` 为空，不读取或写入其他插件的业务表。

### 4.3 其他表引用本插件

当前发行版本预期为无。执行 `plugin purge` 时，安装器仍会查询 `information_schema.KEY_COLUMN_USAGE`；如果发现插件前缀之外的表通过外键引用 `plg_news_*`，将拒绝彻底清理。

非外键的业务逻辑引用无法完全由数据库自动发现。其他插件如需引用新闻数据，必须先声明插件依赖并更新双方数据库说明；禁止绕过服务接口直接写新闻插件表。

## 5. 文件数据

`plg_news_article.cover` 只保存封面相对路径，完整地址由宿主当前存储配置动态补全。

- `plugin remove news` 保留封面文件和上传记录；
- `plugin purge news` 也不会自动删除封面文件；
- 原因是当前上传记录没有强制的插件归属字段，自动删除可能误删共享文件；
- 文件清理必须根据业务记录和 `sys_upload_file` 人工审查后单独执行。

## 6. Remove 与 Purge 影响

### Remove

保留：

- `plg_news_category`；
- `plg_news_article`；
- 新闻插件迁移历史和安装日志；
- 上传文件及上传记录。

删除：

- 新闻插件菜单及角色菜单授权；
- `sys_plugin_menu` 映射；
- `sys_plugin` 当前安装记录；
- 前后端插件源码。

重新安装相同版本时复用迁移历史，不重复创建业务表。

### Purge

在 Remove 基础上继续删除：

- 所有实际存在的 `plg_news_*` 表；
- 新闻插件迁移历史；
- 新闻插件安装日志；
- 宿主归档的插件迁移文件和文档。

Purge 不删除上传文件。Purge 不可恢复，执行前必须备份数据库。

## 7. 安全检查结论

| 检查项 | 结论 |
| --- | --- |
| 是否引用核心业务表 | 否 |
| 是否引用其他插件表 | 否 |
| 是否存在插件外部物理外键 | 发行时无，Purge 前动态检查 |
| 是否允许 Remove | 是，插件停用且无已启用依赖时允许 |
| 是否允许 Purge | 是，完成备份、显式确认且动态外键检查通过后允许 |
| 是否自动删除文件 | 否 |
